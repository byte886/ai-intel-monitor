# 多源调研决策机制（多 AI 群策群力 SOP）

> 2026-10-06 首次实践沉淀：针对"搜索方法论"核心问题，通过外部 Chrome 依次问 Gemini/ChatGPT/Claude/Grok/DeepSeek（先免费版），5 家回答高度一致、零冲突，增量全量吸收。
> 本文档将本次实践 + Grok 结构化回答（存档 `artifacts/ai-consultation/grok.md` ①）固化为可复用机制，**后续遇到重点决策或自身能力不足的问题时启动本机制**。

## 一、触发条件（何时启动）

- 重点决策（影响方向/方案/投资类判断）
- 自身能力不足或信息不足的问题（不确定、需要外部交叉验证）
- 用户点名要求"群策群力/多 AI 交叉验证"

## 二、渠道优先级与使用顺序（默认推荐）

| 阶段 | 优先级 | 渠道 | 类型 | 使用时机 | 付费建议 |
|---|---|---|---|---|---|
| 快速摸底 | P0 | Google / Bing / 百度 | 搜索引擎 | 永远先做 | 免费优先 |
| 通用推理 | P1 | Grok / Claude / ChatGPT / Gemini | 通用大模型 | 同步或紧接搜索后 | 有付费就用最新模型 |
| 中文/垂直 | P2 | DeepSeek / 豆包 / 元宝 | 中文优化模型 | 中文语境/国内政策/本地化时 | 免费优先 |
| 专业数据 | P3 | Perplexity / Consensus / Elicit / You.com | 带引用学术引擎 | 需要证据链/论文/数据时 | 有付费用付费 |
| 补充 | P4 | 自定义调研技能 / 小众工具 | 自建或垂直 | 前序结果不足时 | 按需 |

**默认启动组合**：Google（或 Bing）＋ Grok + Claude（或 ChatGPT）＋ DeepSeek 或豆包（中文场景）＋ Perplexity / Consensus（需要引用时）。
**不需要全部问完**——只有当前组合结论冲突或证据不足时再追加。

## 三、差异化提问原则（不是每个渠道问一样的）

- **搜索引擎**：找原始证据和最新动态
- **通用大模型**：做逻辑推演、多角度分析、方案生成
- **中文模型**：补中国本地化视角（国内政策/数据/实践，标注时效）
- **专业引擎**：要引用和数据支撑（citations + confidence level）
- **绝不把同一段话原封不动复制到所有渠道**——按渠道优势差异化提问

## 四、可直接套用的提问模板

**模板 A 搜索引擎**：
```
[核心问题] site:edu OR site:gov OR site:org OR "研究报告" OR "白皮书" OR "统计数据" -广告 -推广
中文补充：[核心问题] 最新 研究报告 OR 官方数据 OR 政策文件 filetype:pdf
```

**模板 B 通用大模型（第一轮统一框架）**：
```
问题：[完整描述问题]
背景：[简要背景 + 你已有的认知]
要求：
1. 给出 3 种可能的观点/方案，并标明支持证据强度（高/中/低）
2. 指出主要风险与不确定性
3. 给出可执行的下一步行动建议（按优先级排序）
4. 如果信息不足，明确告诉我还需要补充什么信息
请用结构化输出（标题+要点）。
```

**模板 B 第二轮（针对冲突深化）**：
```
刚才你给出了观点X，但其他来源给出了观点Y。请对比两者的假设、数据来源和适用场景，并给出你更倾向哪一方以及理由。
```

**模板 C 中文优化模型**：
```
问题：[核心问题]
请从中国语境出发回答：
1. 国内最新政策、数据或实践是怎样的？
2. 与国际主流观点有何差异？
3. 给出适合中国用户的可落地建议。
请标注信息时效性。
```

**模板 D 专业数据引擎**：
```
[核心问题]
Focus on recent studies, meta-analyses, and official statistics.
Provide citations and confidence level.
```

## 五、标准执行流程（可直接照做）

1. **问题拆解**（5 分钟内）：把大问题拆成 2–4 个可验证的子问题
2. **第一轮快速摸底**（搜索引擎 + 1–2 个通用模型）：模板 A + 模板 B
3. **冲突检测与差异化追问**：发现明显分歧 → 模板 B 第二轮 + 模板 C/D 针对性补充
4. **交叉验证与自我判断**：证据一致性？来源权威性？时效性？是否存在偏见？→ **由主控者加权决策，不是简单投票**
5. **输出可执行结论**（固定格式）：
   ```
   【结论】一句话核心判断
   【依据】3–5 条关键证据（带来源）
   【风险】主要不确定性
   【行动】下一步具体做什么（含优先级）
   【信息缺口】如果还需要补充什么
   ```
6. **归档与迭代**：把本次渠道组合、提问模板、最终结论保存下来，下次同类问题直接复用或微调

## 六、浏览器执行要点（外部 Chrome 实测）

- 统一走外部 Chrome（mac_computer_use_tool plane="bu"），不用应用内浏览器
- 各平台输入框多为自定义编辑器：长中文 type 会截断乱码 → **用剪贴板法**（Bash `pbcopy` 写入 → 页面 click 输入框 → ⌘V 粘贴 → Enter 提交）
- 登录墙（ChatGPT/Claude/Grok/DeepSeek 首次均需登录）：`interaction.request_action(browserControl)` 移交用户，返回后重新观察
- 登录态：Gemini/ChatGPT/DeepSeek 会话长期有效；Claude 可能非自愿登出需重登；Grok 登录后会话可复用
- 读取长回答：轮询等待"正在生成/工作于"消失 → `get_page_text` 分段读尾 → `content_export` 读全文
- 每家回答必须即时存档（`artifacts/ai-consultation/<平台>.md`），格式："回答要点 + 与我们方法论的对比发现"

## 七、机制本身的迭代规则

- 每使用 3–5 次回顾：哪些渠道贡献最大？哪些提问效率低？
- 发现新的高价值工具/渠道，直接插入优先级表
- 某类问题反复出现 → 固化成「专用子模板」（如珠宝搜索方法论 v2 就是由本机制产出）
- 本机制不是一成不变，随实践持续修订
