# 定时更新机制（通用抽取版）

> 完整版与证据见 `../01_渠道矩阵/珠宝AI渠道矩阵_v1.1_20261006.md` 5.7 节（唯一权威源）。本文档为跨行业通用抽取，供任何监控项目直接引用。

## 为什么需要定时更新

搜索/平台规则会变、AI 工具与模型会变、价格会变、渠道源会失效。监控体系必须"分层频率 + 变化信号 + 周期调度 + 写回仓库"闭环，否则矩阵半年后就全是死链和过时价格。

## 一、更新频率分层

| 内容类型 | 频率 | 跑什么 |
|---|---|---|
| 热搜话题与案例 | **每周** | 各平台关键词扫描、趋势工具、行业媒体邮件 |
| AI 工具上新与价格 | **双周** | 逐一访问工具定价页/产品页；核对价格数字、页面/API 双形态、链接可用性 |
| 渠道/平台规则 | **月度** | 抽检入口 URL 是否 404、关键词热度复核（删/加词） |
| 谷歌/搜索算法 | **事件驱动 + 月度核对** | 有更新新闻当场补核，无则月度顺带看 |
| 竞品/开源 Release | **事件驱动（GitHub Watch→Releases 邮件）+ 月度核对** | — |
| 展会赛事日历 | **季度核对** | 年度排期确认一次 |

## 二、每次更新要刷什么（扫描清单）

- **每周（1.5–2h）**：平台关键词 → 平台指数上升关联词 → 行业媒体邮件 → 海外趋势工具（Google Trends/Pinterest Trends/TikTok Creative Center）→ 热榜/新榜/微博热搜 → 产出《每周情报速递》
- **双周（约30min）**：逐一核对监控对象行——①价格数字 ②页面/API 双形态（有没有新增/下线 API）③可用性（链接通不通）；变化写回矩阵对应行 + CHANGELOG
- **月度（约30min）**：渠道矩阵抽检 10 条入口 URL 是否 404；平台入口名是否改名；RSS 失效 feed；过期链接；关键词组热度复核
- **事件驱动**：收到平台改版/工具下架涨价/新工具上榜/GitHub Release/算法更新新闻时，当场定向核对一次

## 三、变化检测信号（什么触发更新）

① 平台改版/规则公告 ② 工具下架/改名/涨价≥20% ③ 新工具上 Product Hunt 榜前列 ④ 已订阅仓库 Release ⑤ 行业媒体头条大事件 ⑥ 搜索算法更新新闻 ⑦ 渠道入口 URL 404。

## 四、更新后沉淀（写回仓库 + 格式）

| 变化类型 | 写回哪 | 时机 |
|---|---|---|
| 价格/形态/链接变化 | 监控清单对应行（行尾加"（YYYY-MM 复核）"） | 每次复核 |
| 影响选型结论 | 对应选型文档 | 仅当影响结论 |
| 所有显著变更 | **CHANGELOG.md 记一条**（编年体只增不改） | 每次 |
| 拿不准/未核实 | **ISSUES.md 登记** | 当场 |

- 版本号：文档头部 `vX.Y` 递增；CHANGELOG 格式：`YYYY-MM-DD ［类型］一句话（+影响/依据）`，类型 = 新增/变更/修复/废弃/移除
- 示例：`2026-10-20 ［变更］双周工具复核：DeepSeek 定价页更新（V4-Flash 输入降至 1–2 元/百万 token 闲时）；某工具迁移生效（✅官方公告）；某档位仍未公开（⚪待验证→ISSUE-XXX）`

## 五、落地方式（定时任务拆分，三条路径）

- **路径 A（推荐·零成本自动）**：GitHub Actions 定时跑扫描 → 每周一 08:00 生成"热榜 + AI 工具日报"推送。cron 示例：`0 0 * * 1`；Actions schedule 有约 15 分钟最晚延迟；放本仓库 `.github/workflows/`
- **路径 B（本机）**：crontab/launchd 每周触发脚本：拉 RSS 未读 → LLM API 摘要 → 输出情报速递文档；双周另跑工具监控清单。脚本只做"采集+摘要"，筛选仍人工
- **路径 C（零部署·人工提醒）**：日历/提醒事项设固定时段执行——**先跑两周验证情报流价值，再决定上 A/B**

## 六、约束衔接

- 所有结论沿用四档标注（✅已查证/🔶经搜索补充/🟡一方说法/⚪未经核实）；价格类标注复核时间点；变化未核实时标"（待验证）"并进 ISSUES
- 不编造：工具下架/涨价/改版一律以官网或官方公告为准，找不到公告标 ⚪
- 启动顺序：①人工跑两周（0 元）→ ②确认有价值 → ③部署自动化（需用户确认），部署后 CHANGELOG 记一条
