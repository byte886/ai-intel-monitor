# 四、开源监控/情报系统（三档价值评估：直接用 / 部分用 / 思路借鉴）

> 用户真实需求："做这种监控需求的功能，有没有人已经做了类似功能的开源项目"。以下均验证存在（给仓库+stars量级+活跃度）。
> **三档评估口径**（不只看技术可用性）：①**可直接用**=功能匹配、可自托管/免费、能直接部署跑起来（标注部署难度）；②**部分可用/可改造**=某个模块有用（某平台抓取器/摘要流程/定时模板），可拆出来复用或改造（标注可用模块）；③**思路借鉴**=即使不部署，其**运营/产品层面的设计思路**也有启发（怎么组织监控源、怎么分层、怎么消化信息、怎么标优先级、怎么去噪音去重、怎么把情报沉淀成库）——这部分比代码更有价值。
> **合规提示**：X/Twitter、IG、FB、TikTok 的 ToS 均禁止未经授权自动抓取，有封禁/违约风险；以下工具大多依赖官方API或第三方数据接口。Reddit/Hacker News 有免费官方API相对友好；微博/知乎/B站无公开社监API（TrendRadar等经第三方聚合取热榜）；抖音反爬严格。

## 4.8 从这些开源项目里能提炼出的监控体系设计思路清单

> 不依赖任何部署，直接可抄的**运营/产品层思路**（比代码更有价值）：

1. **监控源组织**：分层多路并行——热榜层（TrendRadar式多平台聚合：微博/知乎/B站/抖音/PH/HN）、趋势层（工具站/PH 上新）、行业层（媒体RSS/Newsletter）、页面层（changedetection 定点盯梢竞品/展会页）；**无RSS站点用路由桥**（RSSHub/RSS-Bridge 把任意网页变成订阅源）。
2. **信息消化**：AI评分/相关度过滤（Horizon 0-10分）→ 跨源去重 → 分级摘要（标题→一句话→分类），**只推高分项**，不把原始噪音倒给用户。
3. **推送机制**：多渠道（飞书/邮箱/Slack/企微/Telegram）+ 固定节奏（每日/每周一）+ **摘要优先于全文**；推送即"今日值得看"清单，不是全文转储。
4. **优先级标注**：关键词过滤 + 打分排序 + 只盯三类高价值信号（低粉爆款/新上架/价格变动）——监控不是越多越好，是越准越好。
5. **噪音处理**：精确监控点（changedetection 的 XPath 只盯一块内容）；过滤器/规则引擎（FreshRSS）；**Watch→Releases 只收版本通知、不收 issue 噪音**（GitHub 的噪音控制手法）。
6. **沉淀成库**：GitHub Actions 产物/日志留在仓库=自动变更台账；Markdown 日报直接归档进知识库；Release 通知邮件=半自动变更记录——**监控要有记忆，不能看完就丢**。
7. **落到本项目**（即五.7 定时更新机制的设计来源）：情报流 = 源（RSSHub/行业邮件/热榜聚合）→ 消化（关键词+评分过滤+去重）→ 推送（飞书日报）→ 沉淀（《每周情报速递》+ CHANGELOG/ISSUES 台账）。

## 5.7 项目定时更新机制（可持续自更新设计 · 核心诉求）

> 定位：**机制设计 + 建议**——本文件只给方案，不实际创建定时任务；部署由主 Agent 交付后另行执行（可能需用户确认）。设计依据：搜索/平台规则会变、AI 工具与模型会变、价格会变、渠道源会失效，需要"分层频率 + 变化信号 + 周期调度 + 写回仓库"的闭环。

### 5.7.1 更新频率分层（按内容类型）

| 内容类型 | 频率 | 依据与跑什么 |
|---|---|---|
| 热搜话题与案例（抖音/小红书/海外社媒） | **每周** | 时效性强；走五.2 每周扫描清单 |
| AI 工具上新与价格 | **双周** | 价格/形态变化快；走三.7 对比表机制，价格标注复核时间点 |
| 渠道/平台规则类（抖音/小红书规则、热点宝入口名、RSS 源可用性） | **月度** | 规则变化慢但会改版 |
| 谷歌/搜索算法变化 | **事件驱动 + 月度核对** | 有算法更新新闻当场补核，无则月度顺带看 |
| 竞品/开源项目 Release | **事件驱动（GitHub Watch→Releases 自动邮件）+ 每月核对** | 见四.6 / 六.B 订阅清单 |
| 展会赛事日历 | **季度核对** | 年度排期，季度确认一次 |

### 5.7.2 每次更新要刷什么（更新扫描清单）

- **每周（人工 1.5–2h，五.2 模板）**：抖音/小红书关键词 → 抖音指数红色上升关联词 → JCK / National Jeweler / The Jewelry Wire 邮件 → 海外趋势工具（Google Trends / Pinterest Trends / TikTok CC）→ 今日热榜 / 新榜 / 微博热搜 → 产出《每周情报速递》（五.5 模板）。
- **双周（AI 工具，约 30min）**：逐一访问 三.1–三.6 每行的"如何监控"列——火山方舟产品页+文档、DeepSeek 定价页、阿里百炼定价页、Toolify /new、Product Hunt 周榜、GitHub Releases 邮箱；核对三件事：**价格数字、页面/API 双形态（有没有新增/下线 API）、可用性（链接通不通）**；变化写回本矩阵对应行 + CHANGELOG。
- **月度（渠道规则，约 30min）**：渠道矩阵一/二 抽检 10 条入口 URL 是否 404；抖音热点宝/抖音指数入口名是否再改名；Inoreader 失效 feed；Raindrop 过期链接；关键词库 D–G 组词热度复核（哪些涨、哪些没人搜了→删/加）。
- **事件驱动（随时）**：收到平台改版公告 / 工具下架涨价邮件 / PH 新工具上榜 / GitHub Release 通知 / 搜索算法更新新闻时，当场做一次定向核对。

### 5.7.3 变化检测信号（什么触发更新）

① 平台改版/规则公告（抖音创作者中心、小红书专业号、微信小店规则中心）；② 工具下架/改名/涨价≥20%（三.7 阈值）；③ 新工具上 Product Hunt 榜前列，或 Toolify 连续两周出现珠宝垂直新工具；④ 已订阅 GitHub 仓库 Release（四.6 / 六.B 清单）；⑤ 行业媒体头条出现 AI 珠宝大事件（JCK / 中宝协 / 新榜）；⑥ 搜索算法更新新闻（Google 核心更新 / 百度算法公告）；⑦ 渠道入口 URL 404。

### 5.7.4 更新后沉淀（写回仓库 + 格式）

| 变化类型 | 写回哪 | 时机 |
|---|---|---|
| 价格/形态/链接变化 | 本矩阵对应行（行尾加"（2026-XX 复核）"） | 每次复核 |
| 影响选型结论 | 《工具选型参考》§4 / §5 | 仅当影响结论 |
| 影响叙事平台选择 | 《故事塑造平台选型参考》 | 仅当影响结论 |
| 所有显著变更 | **CHANGELOG.md 记一条**（编年体只增不改） | 每次 |
| 拿不准 / 未核实 | **ISSUES.md 登记**（03_进行中的任务/） | 当场 |

- **版本号**：文档头部 `vX.Y` 递增；CHANGELOG 沿用仓库既有约定格式：`YYYY-MM-DD ［类型］一句话（+影响/依据）`，类型 = 新增/变更/修复/废弃/移除。
- **示例条目**：`2026-10-20 ［变更］双周工具复核：DeepSeek 定价页更新（V4-Flash 输入降至 1–2 元/百万 token 闲时）；Remove.bg 迁移 Leonardo 生效（✅官方公告）；Magnific 订阅档位仍未公开（⚪待验证→ISSUE-XXX）`

### 5.7.5 落地方式（定时任务拆分）
